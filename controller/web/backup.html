Backup

The data directory in one encrypted file; a restore is the CLI's.

Download a backup

Encrypt to an age key instead

Restore it with the key's identity file: espdns restore -identity key.txt.

A backup holds the release key and the Wi-Fi passwords, so your login password is asked again before each download.

The passphrase goes to the controller in this request only, over localhost, to encrypt the file: it isn't kept or logged. Keep it apart from the backup (in a password manager). The fleet lock is taken while the files are read, so a backup isn't made while a job or the CLI changes the fleet; then it says who holds it.

Restore

A restore is the CLI's, into a stopped controller's data directory, empty or new: the running controller keeps the login's sessions, the jobs and their dry runs in memory, and a restore replaces the login and the release key, which nothing in this page can do. Every path, size and sum in the backup is checked, and the settings, the release key, the token and the login read as the controller reads them, before anything is put in place.

  1. Stop the controller (docker compose down in controller/).
  2. See what the backup holds and check it, writing nothing: 
    docker compose run --rm -v "$PWD/espdns-backup-….age:/backup.age:ro" \
  --entrypoint /espdns espdns-controller restore -data /data -in /backup.age -dry-run
  3. Restore it (the passphrase is asked; an existing directory that isn't empty is refused, or with -force what is there is moved into .before-restore-<time>/): 
    docker compose run --rm -v "$PWD/espdns-backup-….age:/backup.age:ro" \
  --entrypoint /espdns espdns-controller restore -data /data -in /backup.age
  4. Start the controller on it (ESPDNS_DATA=/path/to/new/data in controller/.env, then docker compose up -d in controller/) and log in with the restored login. Chip images, if the backup has none: load them again with espdns release import (docs/operations.md, Get the firmware into the controller).

Outside Docker: espdns restore -data data -in backup.age [-dry-run] [-force] (-identity key.txt for a backup made to an age key).

Without a backup

The nodes keep running without the controller. A new data directory with the release key imported finds them again: espdns recover reads each node's /status (only reads), writes settings.json with the nodes in service that trust the key, keeps each node's /status in recovered/, and says what is here for its config and hosted zones. The nodes don't return their configs', zones' or lists' contents: copy your own back into the new data directory, or write them again. From controller/, with the new data directory made and named in .env (docs/operations.md, Recovering from the nodes):

docker compose run --rm -T --entrypoint /espdns espdns-controller \
  key import -data /data -key - -pub /keys/release.pub -recovery-pub /keys/recovery.pub < release.pem
docker compose run --rm --entrypoint /espdns espdns-controller passwd -data /data
docker compose run --rm --entrypoint /espdns espdns-controller recover -data /data -dry-run
docker compose run --rm --entrypoint /espdns espdns-controller recover -data /data
